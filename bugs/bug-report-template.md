## Справочник

### Критичность (Severity) — насколько сильно дефект влияет на работу системы

| Уровень | Описание | Пример |
|---------|----------|--------|
| **Critical** | Система не работает, потеря данных, блокирует основной сценарий | Сайт падает при открытии страницы города |
| **Major** | Основная функция работает неверно, обходного пути нет | Поиск не находит существующие города |
| **Minor** | Функция работает, но с недочётами, есть обходной путь | Подсказки появляются с большой задержкой |
| **Trivial** | Косметический дефект, не влияет на функциональность | Опечатка в тексте, сдвиг иконки на пару пикселей |

### Приоритет (Priority) — как срочно нужно исправить

| Уровень | Описание |
|---------|----------|
| **High** | Исправить в первую очередь, до релиза |
| **Medium** | Исправить в ближайших плановых работах |
| **Low** | Исправить, когда будет время |

Severity определяет тестировщик, Priority обычно определяет команда или менеджер продукта. Это разные параметры: опечатка на главной странице имеет низкую критичность, но может иметь высокий приоритет.

### Жизненный цикл дефекта

🆕 New → 👀 Open → 🔧 In Progress → ✅ Fixed → 🔁 Retest → 🔒 Closed

Дополнительные статусы: ❌ Rejected (не дефект), ♻️ Reopened (после ретеста дефект остался), ⏸ Deferred (отложен), 📎 Duplicate (дубликат другого бага).

### Чек-лист хорошего баг-репорта

- [ ] Название понятно без чтения описания
- [ ] Шаги воспроизведения пронумерованы и выполнимы с нуля
- [ ] Указаны ожидаемый и фактический результаты
- [ ] Указано окружение (ОС, браузер, разрешение)
- [ ] Приложены скриншот или видео
- [ ] Описан один дефект, а не несколько сразу
- [ ] Проверено, что такой баг ещё не заведён
- [ ] Нет персональных данных, паролей и токенов
